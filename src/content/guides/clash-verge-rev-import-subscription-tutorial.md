这篇以 Clash Verge Rev 为例，讲电脑端导入机场订阅的完整流程。客户端界面文字会随版本略有变化，但步骤逻辑不变。选择其他客户端的人，可以对照步骤去找对应的功能入口。

## 开始前的准备

- 一个已购买的机场账号，并能登录商家的用户面板；
- 面板里的**导入地址**（一般在「订阅」或「使用教程」页，有「复制订阅」按钮）；
- 电脑系统时间准确。部分协议对时间偏差敏感，时间不对会导致连接失败。

## 第一步：下载客户端

只从项目官方发布页（GitHub 上的项目 Releases 页）下载安装包。不要从来路不明的网盘、论坛附件或搜索结果里的“破解版”下载，客户端可能处理按配置接管的网络流量，来源不可信的风险很大。

按系统选择对应安装包：按项目当前发布资产选择对应系统与芯片架构，不假设每个版本都提供相同安装形式。

## 第二步：导入订阅

1. 打开客户端，进入左侧的「订阅」页面；
2. 在顶部输入框粘贴导入地址；
3. 点击「导入」，稍等几秒，列表里出现一个新的配置；
4. 点击这个配置卡片将其设为当前使用。

如果提示失败，先看后面的排错部分。

## 第三步：选择节点和模式

1. 进入「代理」页，会看到节点分组和节点列表；
2. 模式一般选「规则」，让客户端按规则分流，需要强制全部走代理时再选「全局」；
3. 点击测速按钮，查看各节点延迟；
4. 在分组里选一个你需要的地区节点。

## 第四步：打开系统代理

在「设置」里开启「系统代理」，浏览器和大多数应用就会走代理。如果某些应用不受系统代理控制，才需要考虑 TUN 模式，它通常需要安装服务组件并授予管理员权限，新手可以先不碰。

## 验证是否生效

打开浏览器访问你要用的目标网站。同时观察客户端的流量统计是否在增长。如果网页打不开，不要急着换商家，先按下面顺序排查。

## 排错顺序

| 现象 | 优先检查 |
| --- | --- |
| 导入时报错 | 链接是否完整、前后是否有空格、是否被换行截断 |
| 导入成功但没有节点 | 商家面板里的套餐是否已生效或到期 |
| 节点延迟全部超时 | 系统时间是否准确；本机是否还开着别的代理或安全软件拦截 |
| 部分节点可用、部分不可用 | 可能涉及节点、目标或本地路径；记录条件后比较同地区入口，必要时联系商家 |
| 浏览器不能用但客户端显示正常 | 系统代理是否打开；浏览器是否装了自带代理的扩展 |
| 流量突然用得很快 | 检查是否有后台更新、下载软件走了代理；留意节点倍率 |

## 导入地址的安全

- 不要在公开聊天、截图或论坛贴出完整导入地址；
- 怀疑泄露时，在商家面板「重置订阅」，再按商家说明确认旧地址已被撤销；
- 不要把链接粘贴到来历不明的“在线转换”网站，这等于把账号标识交给了第三方。

## 其他客户端

如果你用的是 v2rayN 这类客户端，逻辑相同：在订阅设置里添加分组和订阅地址，更新订阅，选择节点，再开启系统代理。手机端的选择思路见[手机客户端选择](/guides/mobile-client-choice-for-subscription-import/)。

## 导入前先区分地址与网页

商家首页、账户登录页和客户端配置地址用途不同。把登录网页粘进导入框，即使这个网页能正常打开，也不会自动变成客户端认识的配置。应从已登录的用户面板获取对应客户端的入口，并确认复制结果没有被聊天软件截断。不要为了检查内容而把完整地址发到公共搜索框。

若商家提供多个格式，先选择与当前客户端和内核兼容的一项。名字相似不代表格式相同，旧教程中的按钮位置也可能与新版本不同。导入失败时记录错误类别即可，不需要公开包含账户标识的完整地址。对格式兼容性的疑问，优先查看当前项目文档和商家支持说明。

## 保留一个能够恢复的起点

初次导入时给配置起一个能辨认来源的名称，记下导入时间和客户端版本。先完成最小可用设置，再逐项添加自己的规则。不要同时更换配置、修改网络模式和安装多个插件；否则出现问题时，很难知道是哪一项变化造成的。

如果此前已有正常工作的配置，保留它作为回退选择，不要立刻删除。备份文件可能包含敏感凭据，应放在自己的受控位置，不上传到公开仓库。更新后节点名称或策略组变化时，重新检查当前选中项，不能假设所有旧选择都被完整继承。

## 用两个简单动作验证路径

先访问一个普通网页，确认开启客户端后基本联网没有被破坏；再访问自己确有权限使用的目标服务，观察请求是否完成。客户端出现流量并不能单独证明目标任务成功，因为后台程序也可能产生流量。反过来，目标网页打开也可能使用了浏览器缓存，最好再做一次需要网络返回的小操作。

测试期间不要输入无关敏感数据，也不要把测速按钮的绿色结果当成全部验收。浏览器、终端和其他应用可能遵循不同代理设置，应分别确认常用软件。对于公司电脑，涉及服务安装或系统网络变更前应遵循组织管理要求，而不是绕过现有权限。

## 停用时检查系统网络是否恢复

结束使用时，先关闭客户端控制的系统代理，再退出程序，检查普通网页能否访问。若软件异常退出后网络不通，应检查系统里是否还残留指向本机代理端口的设置，而不是立即卸载所有网络软件。修改前记录原值，避免覆盖单位或学校要求的配置。

重置配置地址后，旧客户端中的保存项可能也需要更新。确认新配置可用，再移除失效项；如果多个设备使用同一账户，应逐台处理，不要遗漏电视或路由器。导入并不是一次完成后永远不用维护的动作，套餐到期、凭据重置和配置格式变化都可能要求重新核对。
